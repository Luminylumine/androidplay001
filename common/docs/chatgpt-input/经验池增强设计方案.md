# 经验池增强设计方案

## 一、当前状态

### 已有组件
- **AppDb.java** (SQLite): `experiences` 表 (id, agent_id, agent_name, title, content, type, time, media), `pools` 表 (多池支持), `experience_pool` (多对多映射), `agent_pool_access` (权限控制)
- **ExpStore.java**: 完整的 CRUD (record/search/delete/list), 多池管理, retention 逻辑按时间+数量
- **Experience.java**: 数据模型 (id, agentId, agentName, title, content, type, time, media)
- **ExperiencePoolActivity.java**: 浏览/搜索/删除 UI, 支持图片查看
- **AgentService.java**: `exp_search`/`exp_record`/`exp_delete` 三个工具已实现
- **PublishExperienceActivity.java**: 用户发布经验界面

### 当前问题
1. **零自动写入**: 只有 Agent 显式调用 `exp_record` 或用户手动发布才会写入, 系统不会自动积累经验
2. **无使用频率追踪**: 经验写入后是静态的, 不知道哪些被检索过, 哪些已过时
3. **留存策略粗糙**: 仅按绝对时间 + 总数量裁剪, 不区分"高频使用的有效经验"和"从未被调用的垃圾"
4. **无自动检索集成**: 经验池是被动的, 不会主动在新会话/新一轮中自动注入相关经验
5. **无编辑功能**: 只能删不能改, 经验写错了只能删除重写

## 二、增强方案

### 2.1 Experience 数据模型扩展

在 `Experience` 类中新增字段:

```java
public class Experience {
    // 已有字段...
    public String id;
    public String agentId;
    public String agentName;
    public String title;
    public String content;
    public String type = "agent"; // 'agent' | 'user' | 'auto'
    public long time = 0;          // 创建时间
    public List<String> media = new ArrayList<>();
    
    // === 新增字段 ===
    public long lastUsedTime = 0;   // 上次被检索/使用的时间 (LRU 核心)
    public int useCount = 0;        // 被检索次数
    public double importance = 0.5; // 重要性评分 (0-1), 自动计算或手动设置
    public String sourceSessionId;  // 来源会话 ID (便于追溯)
    public String tags = "";        // 标签 (逗号分隔, 便于检索)
    public boolean userEdited = false; // 是否被用户编辑过 (编辑后提升重要性)
}
```

### 2.3 自动经验写入 (AutoExperienceWriter)

**触发时机**:

| 触发点 | 写入内容 | 重要性 |
|--------|---------|--------|
| Agent 任务完成 (success) | 任务目标 + 执行步骤摘要 + 结果 | 0.6 (成功经验) |
| Agent 任务失败后恢复 | 失败原因 + 修复方法 | 0.8 (避坑指南, 高价值) |
| 用户确认偏好 (ask_user) | 用户明确表达的偏好/约束 | 0.9 (用户直接确认) |
| 工具执行发现系统限制 | 设备限制 (SELinux/权限/硬件) | 0.7 (环境相关知识) |
| Timer 触发完成任务 | 触发源 + 触发结果摘要 | 0.4 (流程记录) |

**写入策略**:
- **去重**: 按 agentId + title 哈希去重, 同一 Agent 24h 内不重复写相同经验
- **限量**: 每次自动写入最多 1 条, 每轮对话最多 2 条, 防止经验池爆炸
- **延迟写入**: 不在触发点直接写 DB, 而是写入内存队列, 在 AgentService 空闲时批量写入

**Experience 自动生成模板**:
```
[自动] {任务目标/错误摘要}
场景: {应用/设备/上下文}
做法: {关键步骤}
结果: {成功/失败}
```

### 2.4 LRU 留存策略升级

**核心公式** (综合评分用于排序和删除):

```
score = importance * decay(age) + 0.1 * useCount
decay(age) = exp(-age_days / half_life_days)    // half_life = 30 天
```

**留存规则**:
1. **硬上限**: 全局最多 500 条经验 (可在设置中调整)
2. **过期删除**: 超过 90 天未被使用 且 useCount=0 且 importance < 0.5 → 自动删除
3. **超限删除**: 超过硬上限时, 按 score 从低到高删除 (保留高重要性 + 高频使用的)
4. **用户保护**: `userEdited=true` 的经验不会被自动删除 (除非用户手动删)
5. **去重合并**: 新写入经验与已有经验 title 相似度 > 0.8 时, 合并到已有经验 (追加 useCount, 不新建)

**实现时机**: 每次 `recordForAgent` 和 `search` 后触发 `applyRetentionWithScore()`

### 2.5 经验自动检索集成

**每轮 LLM 请求前**, 自动检索相关经验注入 system prompt:

```java
// ContextManager.build() 中:
List<Experience> relevant = expStore.retrieveRelevant(
    goal,           // 当前任务目标
    deviceSnapshot, // 设备状态
    agentId,        // 当前 Agent
    5,              // Top-K
    2000            // 最大总字数
);

// 注入到 system prompt:
// 【相关经验】
// 1) [重要性:0.9, 被引:3次] 不要卸载微信 - 用户确认保留微信
// 2) [重要性:0.7, 被引:1次] /proc/stat 访问被 SELinux 拒绝 - 需 shell 权限
```

**检索算法**:
```
score = 0.4 * textRelevance(goal, exp.title + exp.content)   // 文本余弦相似度简化为关键词命中
      + 0.2 * scopeMatch(exp.tags, deviceSnapshot.foregroundPackage)  // 应用匹配
      + 0.2 * importance
      + 0.1 * recency(now - exp.lastUsedTime)  // 时间衰减
      + 0.1 * usageBoost(exp.useCount)  // 使用次数加分
```

### 2.6 用户可见管理界面升级

**ExperiencePoolActivity 增强**:

1. **列表项显示**:
   - 标题旁显示 `[自动]` / `[用户]` / `[编辑]` 标签
   - 右下角显示: `⭐0.9` (重要性) · `🔁×3` (被引次数) · `📅3天前` (最后使用)
   
2. **长按菜单**:
   - ✏️ 编辑标题/内容 (编辑后 userEdited=true, importance+=0.2)
   - ⭐ 标记重要 (importance=1.0)
   - 🗑️ 删除
   
3. **排序切换**:
   - 按时间 (默认)
   - 按重要性
   - 按使用频率
   - 按"最久未使用" (LRU 视角, 方便清理)
   
4. **筛选**:
   - 只看自动写入 / 只看用户发布 / 只看已编辑
   - 按 Agent 筛选

## 三、实现步骤

### Step 1: 数据层升级
- AppDb 升级到 v3, ALTER TABLE 加列
- Experience.java 加新字段
- ExpStore.java 新增方法:
  - `retrieveRelevant(goal, device, agentId, k, maxChars)` - 智能检索
  - `incrementUsage(expId)` - 增加使用计数
  - `applyRetentionWithScore()` - 基于评分的留存
  - `autoRecord(agentId, agentName, title, content, importance, sourceSessionId)` - 自动写入 (带去重)
  - `updateImportance(expId, delta)` - 重要性调整

### Step 2: 自动写入实现
- 新建 `AutoExperienceWriter.java`:
  - 单例, 内存队列 + 延迟批量写入
  - `onTaskSuccess(agentId, sessionId, goal, steps, result)`
  - `onTaskRecovered(agentId, sessionId, error, fix)`
  - `onUserConfirmed(agentId, sessionId, preference)`
  - `onToolRestricted(agentId, sessionId, restriction)`
  - `onTimerTriggered(agentId, sessionId, trigger, result)`

### Step 3: 检索集成
- 在 AgentService 的 LLM 请求构建前, 调用 `ExpStore.retrieveRelevant()`
- 将结果格式化为 system prompt 段落注入

### Step 4: UI 升级
- ExperiencePoolActivity 增加:
  - 标签显示 (自动/用户/编辑)
  - 元数据显示 (重要性/使用次数/最后使用时间)
  - 长按菜单 (编辑/标记重要/删除)
  - 排序切换 (时间/重要性/频率/LRU)
  - 筛选 (类型/Agent)
- 新建 `EditExperienceActivity.java` 编辑界面

### Step 5: 钩子集成
- AgentService: 在所有完成/失败/确认/限制点调用 AutoExperienceWriter
- TimerEngine: 在触发完成后调用 AutoExperienceWriter

### Step 6: 构建验证
- 构建 APK, 安装到设备
- 测试: 完成任务 → 经验自动写入 → 下次同类任务自动检索
- 测试: 经验编辑 → 重要性标记 → 不会被 LRU 删除

## 四、不需要第三方库

完全使用 Android 原生 API:
- SQLite: `android.database.sqlite` (已使用)
- JSON: `org.json` (已使用)
- 相似度: 简单关键词命中 + 位置加权, 不需要 ML 库
- 去重: 标题哈希 + 编辑距离 (Levenshtein 距离自实现, 约 20 行)

所有代码手写, 不引入任何外部依赖。
