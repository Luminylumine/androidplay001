# AdbManager Windows 桌面工具技术规格与架构咨询

## 1. 项目概述
开发一款基于 C# WinForms 的 Windows 桌面工具，用于管理和控制多台 Android 设备（华为/小米）。
核心依赖：已安装的 `adb.exe` 和 `scrcpy.exe`。

## 2. 核心功能需求

### 2.1 设备自动扫描
*   **扫描范围**：USB 接口和局域网（LAN）。
*   **关键约束**：**不能将 TCP 端口硬编码为 5555**。设备可能使用自定义端口。
*   **挑战**：如何在局域网中高效、低侵入性地发现开启了 ADB 无线调试（Wireless Debugging, 端口随机）的设备？

### 2.2 文件系统访问
*   **功能**：在 Windows 资源管理器风格的界面中浏览手机文件，支持拖拽上传/下载。
*   **技术栈**：通过 ADB 命令（如 `adb shell ls`, `adb pull`, `adb push`）实现。
*   **挑战**：如何在 WinForms 中实现流畅的异步文件列表加载和大文件传输的进度显示？

### 2.3 屏幕共享 (基于 scrcpy)
这是技术难点，需要严格遵循以下规格：

*   **常规传输**：正常情况下传输屏幕内容。
*   **智能带宽优化（差异传输）**：
    *   需求：如果屏幕没有变化（静止），则不传输数据；只有在屏幕发生变化时才传输差异部分，以减小带宽占用。
    *   挑战：`scrcpy` 原生是否支持差异传输或静止帧冻结？如果不支持，是否需要在客户端或服务端进行自定义开发？

*   **手机端熄屏（后台共享）**：
    *   需求：在 PC 端共享手机屏幕时，手机本身的屏幕必须关闭（熄屏），以省电和隐私保护。
    *   挑战：如何通过 ADB 或 `scrcpy` 命令安全地控制手机处于“投屏时自动熄屏”的状态？用户提到的 `settings put system screen_off_timeout -1` 是否有效？是否有更好的 ADB 命令或 `scrcpy` 参数？

请重点回答以下架构设计问题，并给出代码示例或具体方案：

1.  **局域网设备扫描方案**：

    *   如何安全地连接这些设备（配对和认证流程）？

2.  **scrcpy 高级用法与定制**：
    *   `scrcpy` 是否内置了静止检测（idle detection）或只传输变化部分的机制？

    *   文件传输的进度如何实时反馈给 UI？
