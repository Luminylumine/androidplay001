## 实现建议

- 错误码与提示语分离：程序返回稳定 `error_code`，展示层再映射提示语。
- 同一错误码只表达一个原因，避免把“路径不存在”映射成“权限不足”。
- 文件工具失败时，不建议模型自动改走 shell；应先检查路径、范围与文件权限。
- `exp_search` 无匹配属于正常结果，不应作为系统异常处理。
- shell 的“未授权”“未运行”“通道断开”“UID 不足”应使用不同错误码。
- 无障碍动作失败时，优先建议重新读取页面状态，再决定是否重试动作。

### 建议错误返回结构

```json
{
  "ok": false,
  "action": "file_ls",
  "error_code": "FILE_DIR_NOT_FOUND",
  "message": "指定目录不存在。请检查路径拼写或先查看上级目录。"
}
```
